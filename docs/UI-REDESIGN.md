# Редизайн FlipDAW: «Студия как железка» (портативная музыкальная станция)

Русскоязычный документ с предложением по визуальному редизайну интерфейса FlipDAW. Цель — превратить текущий «скролл-стек» веб-страницы в интерфейс портативной музыкальной студии: инструменты-деки на общем столе, разворот по тапу, вторичные контролы прозрачным оверлеем, контролы масштабируются под свободное место, визуальный язык — отсылки к реальному железу из `models/`.

**Статус: ПРЕДЛОЖЕНИЕ (на рассмотрении).** Реализация начинается после принятия плана.

---

## 1. Диагноз текущего UI

Сейчас `LaptopLayout.tsx` — это вертикальный скролл-стек:

```
ProjectBar → TransportBar → StepSequencer(16×16) → Piano → Sampler → DJDeck → Grid + Inspector
```

Проблемы:

1. **Навигация скроллом.** Инструменты спрятаны друг под другом, до DJDeck нужно проскроллить. Это «веб-страница», а не студия.
2. **Вторичные контролы наравне с первичными.** Миксер живёт в отдельном layout-режиме, настройки — модалкой, Инспектор — боковой панелью 280px. Master-громкости визуально нет вообще.
3. **Пустота и мелкость.** На 13" полоски и 24px-кнопки теряются, а свободное место простаивает. TentLayout уже доказал правильный принцип: «контролы увеличиваются под доступное место» (тента 92→168px).

## 2. Сводка принципов из источников

| Источник | Правило, которое берём |
|---|---|
| **Springer «Controls»** (в `models/`) | Кодирование контролов: **≤5 цветов**, значимость через размер и место; движение «вверх / по часовой = увеличение»; тачскрин: мишень ≥18 mm, мёртвая зона 6 mm, активация **на отпускании** для точных контролов |
| **`models/ergonomics_guide.md`** | Мишени ≥48×48 dp, зазор 8–12 mm, закон Фиттса, поворотные ручки → **вертикальные слайдеры / драг**, состояние — LED-заливка всей кнопки, большие триггер-пэды |
| **ISO 11064-5:2008** | Отделять отображение от управления; **зоны**: первичные контролы (часто + важно) — центр/перед, вторичные — границы; консистентное кодирование контролов для снижения ошибок оператора |
| **ISO 9241-161:2016** | Минимумы размеров цифровых контролов, однозначный отклик на действие |
| **iqsdirectory (push-button vs ёмкостные)** | Ёмкостный тач теряет тактильность физкнопки → компенсация **светом и звуком**: LED-заливка, акцентная подсветка, визуальный + аудио-отклик на каждое касание |
| **ГОСТ Р МЭК 60268-18 / IEC (пик-индикаторы)** | **Трёхцветный измеритель уровня**: зелёная рабочая зона, жёлтая предупреждающая, красная перегруз/лимит — для strip- и master-метров |
| **EBU R128 / ITU-R BS.1770** | Опорный уровень **−18…−23 LUFS** с true-peak потолком −1 dBTP; режимы momentary/short-term для master-метра |
| **Apple HIG** | Минимум 44 pt, системные состояния кнопок |
| **Material 3** | Минимум 48×48 dp, состояния enabled / pressed / focused / disabled |
| **NexusUI / Web Audio Controls** | Слайдер + метка + drag-зона **шире самого контрола** (закон Фиттса: ловить за весь трек) |
| **AUv3 / VSTGUI (Steinberg)** | Паттерн «хедер + панель управления + рабочая площадь»; персистентный транспорт поверх; деку-скины «как у железа» |

## 3. Концепция: общий стол с превью-деками

Метафора — **настольная студия**: перед глазами всегда «стол», на котором раскрыт ровно один инструмент; остальные — компактные превью-карточки-модули.

**Анатомия (layout):**

```
┌──────────────────────────────────────────────────────────┐
│  ProjectBar          [сохранено●]   [Настройки ⚙]         │
├──────────────────────────────────────────────────────────┤
│  TransportBar: ▶ BPM ⏱ 4/4 Q Метроном Запись  [master]    │  ← всегда наверху
├──────────────────────────────────────────────────────────┤
│   ╔═══════════════ ДОК ДЕКОВ (превью-модули) ═══════════╗  │
│   ║ [Drum 16×16] [Piano] [Sampler] [DJ Deck] [Grid 8×8] ║  │  ← свернутые
│   ╚══════════════════════════════════════════════════════╝  │
│                                                          │
│        ┌─────────────────────────────────────┐            │
│        │   РАБОЧИЙ ДЕК (развёрнутый модуль)   │            │  ← единственный
│        │   заполняет всё свободное место      │            │     активный инструмент
│        └─────────────────────────────────────┘            │
├──────────────────────────────────────────────────────────┤
│  Footer: [Микшер] [Master vol]        (→ открывают overlay)│
└──────────────────────────────────────────────────────────┘
```

**Как работает:**

- **Превью-модуль** — мини-дашборд инструмента (усечённая сетка, уменьшенные клавиши), рендерится *живым* (состояние обновляется). Тап → разворот.
- **Развёрнутый дек** занимает всю среднюю зону; масштаб контролов растёт до заполнения (container-query: `--scale` через `cqw`, как в Tent). У каждого модуля есть кнопка «⋏ свернуть» и свайп вниз / жест «назад».
- **Транспорт и ProjectBar всегда персистентны** — не скроллятся, не прячутся. Переход превью ↔ дек — анимация (flip, ~200ms), без смены layout-режима.

## 4. Вторичные контролы = прозрачный оверлей

Микшер, master-громкость, Settings, Mapping — **не отдельный экран**, а панель поверх рабочего дека:

- Полупрозрачное стекло: `background: color-mix(in srgb, var(--panel) 82%, transparent)` + `backdrop-filter: blur(8px)` → «прозрачность ~20 %»: дек виден и продолжает играть.
- Открывается слайдом (справа или снизу), закрывается тапом вне панели или «✕».
- Раньше это были отдельный `MixerLayout` и модалки — теперь один слой.
- Внутри: вертикальные фейдеры (tracks + master), на каждом колонка-метр с трёхцветной зоной (ГОСТ Р МЭК 60268-18), кнопки M/S с LED-заливкой, компактный кривой EQ сверху.

---

## 5. Анти-пустота: скейлинг контролов (Tent-принцип)

Правило: **контент сам заполняет доступное место** (не наоборот — не центрировать кучку контролов в углу).

- Размеры контролов и шрифт на `--scale`, получаемом из контейнерного запроса:
  `container-type: inline-size; font-size: clamp(14px, 2cqw, 26px);`
- Где места много — 96px контролы против базовых 48px (в точности как Tent поднял cell 92→168px).
- Слайдеры: drag-зона = весь трек (высота 100 %), палец за законом Фиттса ловит за любую точку, а не за 22px-ручку.

## 6. Скины деков по 3D-моделям из `models/`

Каждый модуль получает «шкурку» реального железа (без 3D-рендера — это CSS/тени/плашки, но **пропорции и раскладка контрол-групп** берутся из моделей):

| Модуль | Референс в `models/` | Что берём |
|---|---|---|
| **Drum (StepSequencer)** | `Roland TR-909.3dm` | 16 шаговых пэдов, row-LED (цвет = голос), легенды инструментов снизу, «точечные» индикаторы |
| **DJ Deck** | `CDJ3000.stp`, `CD_CDJ_2000.STEP`, `Pioneer_DJM_2000_Nexus_Mixer.STEP` | волна как CDJ-дисплей, колонки EQ (Hi/Mid/Lo), кроссфейдер с рифлёным центром, «джог» для скролла позиции |
| **Piano** | `Casio VL-1.stp`, `Moog Source.igs` | панель-«голова» над клавишами (октава/волна — винтажный вид), белые клавиши с пластиковым телом, чёрные — тёмный скос |
| **Sampler** | `Hercules DJControlMix v9.3mf`, `mdj-900-1.snapshot.3.zip`, `roland-v8-hd-1.snapshot.5.zip` | 4 крупных пэда-«подушки» (в духе MPC/SP-пэдов), ободок-подсветка при звучании |
| **Grid / Микшер** | `Mixer Assembly1.stp`, `Technics_SL-1200.stl` | плашки каналов, фейдеры с 0 dB-маркировкой, метры с зонами |
| Фон-пластик | `Grab.stl` | текстурированный хардверный фон панелей |

Скины — чистый CSS (тени, бордеры, градиенты панелей); модели используются как референсы **пропорций раскладки**.

## 7. Контрол-спецификация (консолидация стандартов)

- **Триггеры** (пэды/клавиши/клетки): срабатывание **на касании** — задержка важнее отмены («ошибка → свет»); мгновенный LED-отклик как компенсация тактильности (iqsdirectory).
- **Точные изменения** (фейдер, EQ, BPM, кроссфейдер): срабатывание **на отпускании**, drag-зона широкая, дискретный шаг (0.5/0.1 dB), численное значение рядом всегда (tabular-nums).
- **Movement compatibility** (ISO 9241 / Springer): вверх / по часовой = больше. Вертикальный фейдер: вверх = громче. Горизонтальный: вправо = больше.
- **Цвет** — не более 5 активных одновременно: голос/ряд (row), один акцентный «живой» (`--accent`), жёлтый — предупреждение, красный — перегруз/ошибка.
- **Метры (ГОСТ Р МЭК 60268-18 + EBU R128):** зелёная зона до −6 dBFS, жёлтая −6…0, красная — перегруз/лимит. Master-метры: два режима — PPM-обмотка (пики) и loudness-бар (~−18 LUFS), переключение в Settings. Ballistics: подъём мгновенный, спадание ~2.8 c.
- **Мёртвая зона ~6 mm** между соседними контролами — особенно между фейдерами микшера и рядами пэдов.

## 8. Этапы внедрения

**Фаза A — каркас (структура, без нового дизайна).**
`StudioLayout` вместо `LaptopLayout`: Workspace + DockDecks (превью), состояние `activeDeck` в `store/ui.ts`, персистентный тулбар (ProjectBar + TransportBar), клиент оверлея (`BackdropOverlay`), container-query `--scale`. Старый `LaptopLayout` остаётся как режим «Классика» (fallback на малых экранах / по желанию в настройках).

**Фаза B — контролы.**
Внедрить спецификацию раздела 7 во все модули: drag-зоны, шаги, метры с цветными зонами, movement compatibility, добавить master-метр с режимами.

**Фаза C — скины железа.**
По очереди: Drum (TR-909) → DJ (CDJ/DJM) → Sampler (пэды) → Piano (VL-1/Moog). Раскладка групп — из `models/`.

**Фаза D — оверлеи.**
Микшер / мастер / настройки ⇒ полупрозрачный слой; отказ от переключения layout ради микшера.

---

## 9. Критерии готовности

1. Навигация между инструментами — без вертикального скролла: превью + разворот по тапу.
2. Вторичные контролы открываются оверлеем с «прозрачностью 20 %» и не вытесняют рабочий дек.
3. На каждом доступном размере экрана контролы увеличиваются под свободное место (нет «кучки в углу»).
4. Дек-скин каждого модуля визуально опирается на свой 3D-референс из `models/`.
5. Минимумы тач-мишеней ≥48px (tent ≥96px) соблюдены во всех новых компонентах.
6. `npm run typecheck`, `npm run lint`, `npm run build` зелёные; существующие тесты не падают.
